# 工作日志模板生成（Worklog Template）

## Overview

把用户既有幕布工作日志（如《2026--Agent爆发之年》）的记录格式固化，按国家法定节假日安排与工作日规则，自动生成全年或补齐剩余部分的工作日志模板（Markdown 骨架，可落库幕布）。

- 格式规范（周标题/日期节点/跨月/节假日/备注）：先读 `references/worklog-format.md`
- 节假日知识（官方安排/调休/非双休判断/来源）：先读 `references/holidays-cn.md`
- 脚本（生成/补齐 Markdown）：`scripts/worklog_template.py`（已实测，内置 2026 数据）

## 格式速览（完整规范见 references/worklog-format.md）

```
# 0104-09            ← 周标题：MMDD-MMDD（连续工作日，含调休上班的周末）
- 4                  ← 日期节点：段内首月不补零（- 4、- 12）
  - 工作事项
- 30                 ← 跨月段内首月最后几天（- 30、- 31）
- 0401               ← 进入新月的首日：- MMDD
- 02                 ← 新月其余日补零：- 02、- 03
> 周备注             ← 幕布 note，挂在周标题
# 0213-23-春节假期    ← 节假日周：无日期节点，可跟 > 官方安排备注
```

硬规则：
- 工作日 = 周一至周五 + 调休上班日 − 节假日区间；双休日不生成节点（除非调休上班/加班）。
- 节假日节点（非双休）：`# MMDD-MMDD-节假日假期`，按时间插入，无日期子节点，附 `> 描述`。
- 单日周 `# 0530`；特殊后缀：`【N号请假】`、`-加班`。

## 工作流

### 步骤 1：读取与定位

- 幕布文档：按 mubu-mcp 技能读取（`mubu_get_doc doc_id as_markdown=True`）；本地 Markdown 直接读。
- 解析既有周标题，确定「最后已记录周」的结束日期；识别已有节假日/调休标注（用户文档常已含 0104-09、0224-28 等调休周，用于交叉验证官方数据）。

### 步骤 2：核实节假日与工作日（每次必做）

- 打开 `references/holidays-cn.md`：内置 2026 官方安排（国办发明电〔2025〕7号，来源 gov.cn）。**其他年份必须先用当年官方通知替换数据**（国务院每年 11 月发布次年安排）。
- 用 `calculator` 工具逐日核算星期，不得凭记忆推算；调休上班日（2026：1/4、2/14、2/28、5/9、9/20、10/10）要计入工作日。
- 用户口径：法定假日当天为周日、但假期含工作日的（如 2026 清明 4/4-6 含周一 4/6）也算非双休、需补齐。

### 步骤 3：脚本生成 Markdown

```bash
# 模式 A：从零生成全年骨架（含全部非双休节假日节点）
python scripts/worklog_template.py --year 2026 --output full_2026.md

# 模式 B：基于现有文档补齐（保留原文，插入缺失节假日、追加剩余工作日周）
python scripts/worklog_template.py --year 2026 --input existing.md --output filled.md

# 自定义年份：--holidays holidays.json（结构同脚本内置 HOLIDAYS_2026）
# 不带官方安排备注：--no-desc
```

- 脚本输出为幕布可导入的 Markdown 骨架：`#` 第 1 层平铺、`- ` 第 2 层日期节点、`> ` 备注。
- 生成后抽查：节假日节点按时间插入、跨月周格式（`- 30 / - 0401 / - 02`）、最后一组不满 5 天（如 `# 1228-31`）。

### 步骤 4：幕布落库（可选，用户要求时）

幕布创建保真要点（详见 mubu-mcp 技能，踩坑经验）：
- **官方 markdown 导入器会把所有 `#` 折叠成单个根节点的子树**，层级/备注不符合平铺习惯 → 还原平铺结构须走 MubuClient 直接 API（`create_doc` + `POST /v3/api/colla/events` 的 create 事件）。
- 推荐路径：读取原文档 JSON 树（保留既有节点、note、finish 标记）→ `deepcopy` → 按锚点插入节假日节点 → 追加新周节点 → 生成顶层 create 事件平铺写入。
- **根节点必须 detach children**（`root["children"] = []`），否则同批 id 二次创建报 `node id to create existed`。
- 备注 note 用 `"<span>…</span>"` 写入；checkbox（finish 标记）保留。
- 创建后读回导出（`mubu_get_doc as_markdown=True`）逐行对比，验证零丢失、仅新增目标节点。
- 测试文档用后即删，避免污染账号。

### 步骤 5：验证

- 模式 B 与源文档 Diff：相似度应 ≥0.99，缺失 0，仅多出新增节假日节点。
- 全部周标题按时间递增；日期节点与 calculator 核算的星期一致。
- 交付时给出新文档链接，确认原文档未改动。
